# Safe-Net: как превратить проект в сильную активность

Дата: 30 сентября 2026. Это план будущей работы. Отзыв профессора, исследование и измеренный эффект пока не получены.

## Что уже можно показать

Работающий локальный прототип, открытая архитектура, двуязычный контент, собственная логика объяснимых правил и проверяемые инженерные результаты. Презентация подходит для просьбы о методологическом отзыве. Проверки Chrome, внешней почты и hosted CI можно отложить до подготовки публичного демо; в материалах они остаются непроверенными.

## Рекомендуемый следующий результат

Сначала независимый разбор ошибок URL-детектора. Он использует уже работающий движок и может дать воспроизводимый результат без набора участников. Пользовательское исследование обучения — второй этап после согласования методики. Не смешивать точность детектора и улучшение навыка человека.

| Этап | Конкретная работа | Что останется как доказательство | Примерная длительность |
| --- | --- | --- | --- |
| 1. Пакет для отзыва | Прочитать одну релевантную работу выбранного профессора, записать свои инженерные решения и вклад, снять короткое видео курса и URL-сканера | PDF, README, видео 60–90 секунд, точный список собственного вклада | 2–3 вечера |
| 2. Узкий вопрос | Подготовить одно персональное письмо о переносе навыка или метрике предупреждений; после самостоятельного решения отправить одному адресату | Отправленное письмо и дата в личном журнале | 1 вечер, ожидание ответа непредсказуемо |
| 3. Детекторный эксперимент | Определить лицензионно допустимые источники, схему меток, дедупликацию и отдельные источники для настройки/теста; включить сложные легитимные URL | Версионированный набор или воспроизводимая процедура его получения, frozen protocol | 1–2 недели |
| 4. Измерение | Сравнить правила, опциональную модель и blend; записать confusion matrix, false-positive rate, recall, latency и ошибки по языку/семейству атак | Скрипт запуска, реальные таблицы, анализ ошибок и ограничений | Около 1 недели |
| 5. Итерация | Исправить один класс ошибок на development split, один раз оценить зафиксированный тестовый split | До/после на честно разделённых данных, tagged release, changelog | Около 1 недели |
| 6. Пилот обучения | После подходящего review/consent проверить процедуру с новыми наборами заданий и отложенным замером; заранее определить исходы, пропуски и исключения | Протокол, обезличенные результаты или агрегаты, отчёт с attrition | Несколько недель, зависит от согласований |

Сроки — ориентиры для планирования, а не обещание результата или ответа профессора. Размер выборки и число URL определяются методикой; заранее красивые числа не нужны.

## Что реально усилит описание активности

- Решение конкретной проблемы с собственными объяснимыми инженерными решениями.
- Разбор недостатков своего инструмента, включая ложные срабатывания.
- Результат, который другой человек может воспроизвести по опубликованным инструкциям.
- Документированная реакция на отзыв: вопрос, рекомендация, изменение, проверка.
- Работа с реальными пользователями только после подходящей подготовки и согласий.

Не писать «research collaboration», «validated by Professor …», «X% improvement» или количество пользователей, если этого нет. Не называть человека advisor без согласия. Не публиковать его письмо без разрешения. Третьесторонние модели, зависимости и AI-помощь описывать точно.

## Риски перед публичным демонстрационным запуском

| Остаток | Для PDF и локальной защиты | Для работающего публичного сервиса |
| --- | --- | --- |
| Guard в установленном Chrome | Не блокирует объяснение архитектуры; не утверждать, что проверен | Важен: реальные разрешения, first-run, обновление и приватность |
| Настоящий почтовый ящик | Не блокирует отзыв о проекте | Важен для регистрации и восстановления; Mailpit не доказывает внешнюю доставку |
| Дополнительные браузерные сценарии | Можно вынести в ограничения | Важны для надёжности, доступности и разных устройств |
| Внешний CI | Не блокирует PDF | Важен для повторяемой сборки опубликованного коммита |

## Честное краткое описание сейчас

Built Safe-Net, a bilingual cybersecurity learning prototype with server-graded simulations and a shared explainable URL rule engine for the web and a Chrome extension. Documented local regression checks, privacy boundaries and a proposed evaluation of transfer to unfamiliar phishing examples.

Это описание следует адаптировать под реальный личный вклад. Оно не утверждает завершённое исследование или влияние на пользователей.
